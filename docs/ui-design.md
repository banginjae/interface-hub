# Interface Hub - UI Design

## 1. 문서 상태

2차 화면 설계다. 컴포넌트 코드는 아직 없다.

데이터 형태는 `docs/database.md` 13장과 1:1로 대응한다. 화면에서 입력한 값은 모두 저장되고, 다시 열면 같은 칸에 돌아온다. 사용자를 DB 컬럼 이름에 맞추지 않는다.

권한별 버튼은 `docs/requirements.md` 4.3의 표를 그대로 따른다.

---

## 1.1 구현 단계의 화면

P0 화면은 로그인, 최소 계정, 프로젝트, API 편집, API 조회, 이력과 비교, Markdown이다.

MQTT, WebSocket, 장비 프로토콜, 일반 문서, 에러 코드는 P1이다. P0 내비게이션에 활성 탭으로 넣지 않는다. 저장되는 폼이나 예시 데이터를 보여 주지 않는다. 문구로 준비 중임을 알릴 수는 있다.

P0의 API 편집기에는 에러 코드 선택 칸을 두지 않는다. P1에서 같은 항목 화면에 칸을 추가한다.

## 2. 두 개의 모드

작성과 조회는 같은 URL의 다른 모드다.

| 모드 | 목적 |
|---|---|
| 조회 | 목록, 표, 예시, 에러 코드, 최종 수정자, 이력으로 읽는다 |
| 편집 | 항목 하나의 양식만 고친다 |

READ는 조회와 Markdown만 본다. WRITE와 MASTER는 ACTIVE 프로젝트에서 편집으로 들어간다.

ARCHIVED 프로젝트는 조회와 Markdown만 가능하다. 편집 버튼, 항목 추가, 일반 문서 작성, 에러 코드 수정, 멤버 변경, 제목 변경을 숨긴다. 상단에 "보관된 프로젝트입니다. 수정하려면 생성자 또는 MASTER가 복구해야 합니다."를 보여 준다. 복구 버튼은 생성자와 MASTER에게만 보인다.

## 3. 정보 구조

```text
/login
/reset-password
/account/password

/projects
/projects/new
/projects/:id

/projects/:id/api
/projects/:id/mqtt
/projects/:id/websocket
/projects/:id/protocol
/projects/:id/docs
/projects/:id/docs/:docId
/projects/:id/errors
/projects/:id/history
/projects/:id/members

/master/users
```

프로젝트 안 탭:

```text
개요 | API | MQTT | WebSocket | 장비 프로토콜 | 일반 문서 | 에러 코드 | 변경 이력 | 멤버
```

권한이 없는 사용자가 상세 URL로 오면 API 403 문구만 보여 준다.

MASTER에게만 `계정` 메뉴를 보여 준다.

멤버 탭의 부여·변경·회수 버튼은 MASTER와 그 프로젝트 생성자에게만 보여 준다. WRITE 멤버에게는 목록만 보여 준다. 생성자 행에는 권한 변경과 제거 버튼을 두지 않는다.

---

## 4. 프로젝트 목록, 개요, 산출물

목록 열은 제목, 상태, 생성자, 생성일, 내 권한이다. ACTIVE와 ARCHIVED를 함께 보여 준다. 설명과 문서 내용은 목록에 없다.

권한이 없는 행은 열리지 않는다.

개요에는 설명, 공식 문서 4종의 생성 여부, 각 문서의 최신 version과 수정자, 일반 문서 수, 부서별 문서 수, 에러 코드 수를 둔다.

일반 문서 수는 부서 문자열이 같은 것끼리 묶는다. SW, APP, FW, GW, HW와 그 밖의 입력이 한 프로젝트에서 같이 보이게 하는 것이 종료 산출물 조회의 기본 화면이다. 부서 철자는 자유 입력이므로 완전히 같은 문자열만 묶는다.

제목과 설명의 수정, 보관, 복구는 생성자와 MASTER만, ACTIVE에서만 한다. 보관 중에는 복구만 할 수 있다.

아직 행이 없는 규격은 "아직 등록되지 않았습니다"와, 권한이 있으면 `API 규격 만들기` 버튼이다. 생성은 빈 문서 1개를 만드는 요청이다. 네 종류를 한꺼번에 만들지 않는다.

## 5. 규격 공통 레이아웃

조회:

```text
상단: 문서 제목, version, 최종 수정자, 수정 시각
      [편집] [Markdown 복사] [다운로드]
왼쪽: 항목 검색과 목록
오른쪽: 선택한 항목의 읽기 전용 문서
```

편집:

```text
상단: 같은 문서 정보, [조회로 돌아가기]
왼쪽: 항목 목록, 추가, 순서
가운데: 선택한 항목만의 양식
오른쪽: 그 항목의 미리보기
하단: 변경 사유, [이 항목 저장]
```

너비가 좁으면 미리보기는 양식 아래로 내린다.

저장 버튼은 문서 전체가 아니라 선택 항목이다. 다른 항목의 입력칸은 요청에 포함되지 않는다.

문서 상단(Base URL, 브로커, 연결 URL, 전송 방식)은 별도 영역이다. `상단 정보 저장`은 overview만 보낸다.

항목 순서 변경은 `순서 저장`으로 분리한다. 목록의 UUID 집합이 서버와 다르면 저장하지 않고, 목록을 다시 받은 뒤 순서를 다시 맞추게 한다.

1차에 문서 삭제 버튼과 문서 초기화 버튼은 없다.

항목 삭제는 있다. 그 Endpoint나 Topic만 지운다. 확인 문구에 변경 사유를 받는다. 문서 ID와 다른 항목은 남는다.

## 6. 필드 편집기

네 규격이 같은 `FieldTreeEditor`를 쓴다. 장비 프로토콜만 바이트 열을 추가로 보여 준다.

한 행에서 할 수 있는 일:

- 추가, 삭제
- 위아래 순서
- 이름, 타입, 필수, 설명, 예시 문자열
- 타입을 object로 바꾸면 하위 필드 영역이 열린다
- 타입을 array로 바꾸면 요소 타입 하나가 열린다
- enum이면 값 목록
- 타입을 바꾸면 그 타입에 맞지 않는 하위 구조는 지우기 전에 확인한다

중첩은 8단까지다. 배열 원소를 값마다 반복 입력하지 않는다.

선택 필드는 필수 체크를 끈 것이다.

예시 JSON:

- 기본은 자동 생성이다. 필드 예시로 미리보기를 만들고, 저장 시 서버가 그 결과를 저장한다.
- `예시 JSON 직접 수정`을 켜면 텍스트 영역을 연다. 사용자는 필드 트리를 표로 계속 편집한다. Markdown 표 문법은 입력하지 않는다.
- 직접 수정 내용이 JSON으로 파싱되지 않으면 저장을 막는다.
- 파싱은 되지만 필수 누락, 타입 불일치, 트리에 없는 키, nullable이 아닌 null이면 저장을 막는다. 경고만 하고 넘기지 않는다. 이 예시가 AI 도구의 구현 기준이 되기 때문이다.
- 선택 필드가 예시에 없는 것은 저장할 수 있다.

자동 생성으로 돌아온 뒤에는 서버에 저장된 예시와 트리가 일치한다. 직접 수정으로 저장된 예시도 위 검사를 통과한 것만 남는다.

장비 프로토콜의 HEX는 이 JSON 검사와 별도다. JSON 해석 예시는 디코딩 참고이고, 와이어 형식은 바이트 표와 HEX다.

## 7. API 편집기

문서 상단: 제목, Base URL, 공통 인증, 공통 헤더.

목록의 한 줄은 Method 배지와 경로다. 사용자는 한 Endpoint를 고친다.

그 항목의 양식:

- Method, Path
- 기능 설명
- 이 Endpoint의 인증. 문서 공통 인증을 쓸지 개별 지정할지
- Header, Path, Query 표
- Request Body의 Content-Type, 필드 트리, 예시
- Response를 여러 개 추가. 이름, HTTP 상태, 설명, 필드 트리, 예시
- 관련 에러 코드 검색과 선택. 에러 코드 화면이 생기기 전에는 빈 목록으로 둔다
- 변경 사유

`{deviceId}`가 Path Parameter 표에 없으면 저장 전에 경고한다. 1차에는 경고만 하고, 저장 금지는 하지 않는다. 파라미터 표가 기준이고 경로 문자열은 사람이 읽는 이름이다.

조회는 Method와 경로를 제목으로 하고, 파라미터 표, Request, Response별 표와 JSON, 에러 코드 표를 순서대로 보여 준다. 중첩 필드는 `params.speed`처럼 점 경로로 편다. 배열은 `items[].id`로 적는다.

---

## 8. MQTT 편집기

문서 상단: 브로커 주소, 프로토콜 버전, 공통 인증.

항목 하나:

- Topic
- Publisher, Subscriber. 태그 입력
- QoS, Retain
- 방향
- 용도
- Payload 필드와 JSON 예시
- 대응 Topic. 같은 문서의 다른 항목을 선택
- 관련 에러 코드
- 변경 사유

조회는 Topic을 제목으로 하고 QoS, Retain, 방향, 발행·구독 주체, Payload 표, 예시, 대응 Topic, 에러 코드를 보여 준다.

---

## 9. WebSocket 편집기

문서 상단이 연결 규격이다.

- 연결 URL
- 인증
- 하트비트 설명
- 종료 코드 표. 행 추가

항목 하나는 메시지다.

- 이벤트 이름
- 방향: 클라이언트→서버, 서버→클라이언트, 양방향
- 종류: Request, Response, Event
- 설명
- Payload와 예시
- 대응 메시지
- 관련 에러 코드
- 변경 사유

조회는 연결 정보를 먼저 읽고, 메시지마다 방향과 종류 배지를 붙인다.

---

## 10. 장비 프로토콜 편집기

JSON 메시지만 있는 프로토콜로 한정하지 않는다.

문서 상단: 전송 방식, 기본 엔디언, 프레이밍 설명.

항목 하나:

- 명령 이름
- Command ID. 입력한 문자열을 그대로 저장한다
- 요청, 응답, 이벤트
- 설명
- 필드 표. 공통 열에 Offset, Length, Endian, Encoding, 길이 방식, 비트 위치와 비트 길이를 둔다
- HEX 예시. 비워 둘 수 있다
- 해석 JSON. 자동 생성 또는 직접 수정. 와이어 형식을 대체하지 않는다
- 대응 명령
- 관련 에러 코드
- 변경 사유

Encoding이 BITFIELD일 때만 비트 칸을 연다.

FIXED 구간의 Offset이 겹치면 해당 행을 표시하고 저장을 막는다. Offset을 아직 모르는 행은 비워 두고 저장할 수 있다.

조회는 명령을 제목으로 하고, 바이트 표를 Offset 순으로 보여 준 뒤 HEX를 붙인다. 해석 JSON은 그 아래 접이식 영역이다. HEX의 바이트 수와 표의 고정 길이 합이 다르면 조회 화면에 "HEX 길이와 고정 필드 합이 다릅니다"를 보여 준다. 저장 자체는 막지 않는다.

## 11. 충돌

항목 저장이 409 `DOCUMENT_VERSION_CONFLICT`이면 다음 순서로 동작한다.

1. 그 항목 양식의 값은 그대로 둔다.
2. "다른 사용자가 먼저 저장했습니다. 이 항목의 입력은 남아 있습니다. 다른 항목은 이 저장에 포함되지 않습니다."를 보여 준다.
3. `최신 버전 보기`는 서버 문서를 조회해, 같은 항목의 최신본과 내가 편집중인 값을 나란히 보여 준다. 양식을 최신본으로 바꾸지 않는다.
4. 그 사이에 바뀐 다른 항목 이름을 요약으로 보여 준다. 그 항목의 필드를 내 요청에 싣지 않는다.
5. `이 항목을 최신 버전 기준으로 저장`을 눌렀을 때만 요청 version이 최신값이 된다. 그 전에는 자동으로 다시 보내지 않는다.
6. 같은 항목을 다른 사람이 이미 고친 경우에는 "다시 저장하면 이 항목만 내 내용으로 바뀝니다"를 확인받는다.
7. 성공하면 초안을 지운다.

초안 키는 `draft:{documentId}:{itemUid}:{baseVersion}`다. 다른 Endpoint 초안을 덮지 않는다.

대상 항목이 이미 삭제되어 404이면 양식은 유지하고, 삭제한 사람을 이력에서 보여 준다. 그 입력으로 항목을 자동 재생성하지 않는다. 사용자가 `새 항목으로 저장`을 눌렀을 때만 생성 API를 호출한다.

순서 저장이 `ITEM_SET_CHANGED`이면 순서를 적용하지 않고 목록을 다시 받는다.

## 12. 이력과 비교

규격 문서의 이력 목록은 version, 시각, 수정자, 사유, 요약이다. 요약은 "POST /login 수정"처럼 summary의 이름과 op를 쓴다.

비교는 두 version을 고른다. 기본은 직전과 최신이다.

화면 상단:

- 추가된 항목
- 삭제된 항목
- 수정된 항목
- 문서 상단 변경 여부

수정된 항목을 고르면 이전과 이후의 조회 모드를 나란히 보여 준다. 추가와 삭제는 있는 쪽만 보여 준다. 편집 컨트롤은 없다.

일반 문서는 두 Markdown을 나란히 보여 준다.

에러 코드는 그 코드의 이전 값과 이후 값을 표로 보여 준다. 규격 문서 version과는 목록을 섞지 않는다.

---

## 13. 일반 문서

프로젝트 산출물의 목록이다. 부서, 제목, 최종 수정자, 수정일로 거른다.

편집:

- 제목
- 담당 부서. 입력 제안은 하되 후보를 DB 마스터로 강제하지 않는다
- Markdown과 실시간 미리보기
- 변경 사유

일반 문서는 본문 전체가 한 저장 단위다. 규격 항목 API를 쓰지 않는다. 409이면 편집 중인 Markdown을 유지하고 최신 본문을 옆에 보여 준 뒤, 사용자가 확인하면 그 문서 전체를 새 version으로 저장한다.

삭제하면 목록에서 빠진다. 이력의 마지막 스냅샷은 남는다. 1차 목록에서는 삭제된 문서를 보여 주지 않는다.

복사와 다운로드는 규격 문서와 같은 위치에 둔다.

---

## 14. 에러 코드

표 열은 코드, 분류, 설명, 참조 수다.

편집 칸은 코드, 분류, 설명, 발생 조건, 처리 방법이다. 참조 항목은 링크로만 보여 준다.

행마다 version이 있다. 다른 코드를 편집 중이어도 이 행의 저장과 충돌하지 않는다.

참조가 있으면 삭제 버튼을 막고 참조 위치를 보여 준다.

규격 편집기의 코드 선택은 이 목록을 검색한다. 항목 화면에서 코드를 즉시 만들지는 않는다.

---

## 15. 계정

로그인은 사번과 비밀번호다. 실패 문구는 "사번 또는 비밀번호가 올바르지 않습니다."

MASTER 목록은 사번, 성명, 이메일, 역할, 활성이다. 생성은 개별 폼이다. 일괄 등록 화면은 없다.

비밀번호 초기화는 확인 후 메일을 보낸다. 성공은 "설정 링크를 보냈습니다"만 보여 준다. 실패는 "메일을 보내지 못했습니다"만 보여 준다. URL과 토큰은 보여 주지 않는다.

`/reset-password`는 새 비밀번호와 확인이다. 만료, 사용됨, 취소, 형식 오류는 같은 실패 문구다.

본인 비밀번호 변경은 현재 비밀번호와 새 비밀번호다.

## 16. Markdown 예시

서버 출력과 복사 결과가 같다. 최신 저장본만 사용한다.

### API

```markdown
# 포장 라인 — API 규격

- 버전: 12
- 최종 수정: 2026-11-03T06:20:00Z / 홍길동
- Base URL: https://lab.example
- 공통 인증: Bearer

## POST /devices/{deviceId}/commands

장비에 명령을 전달한다.

- 인증: Bearer

### Headers

| 이름 | 타입 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| X-Request-Id | string | 아니오 | 요청 추적 | req-1 |

### Path Parameters

| 이름 | 타입 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| deviceId | string | 예 | 장비 식별자 | dev-01 |

### Query Parameters

| 이름 | 타입 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| dryRun | boolean | 아니오 | 실행 없이 검증 | false |

### Request Body

| 이름 | 타입 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| command | string | 예 | 명령 이름 | start |
| params.speed | integer | 아니오 | 속도 | 10 |

```json
{
  "command": "start",
  "params": { "speed": 10 }
}
```

### Response 200 성공

| 이름 | 타입 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| accepted | boolean | 예 | 접수 여부 | true |

```json
{ "accepted": true }
```

### Response 409 거부

| 이름 | 타입 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| reason | string | 예 | 거부 이유 | offline |

### 에러 코드

| 코드 | 설명 | 발생 조건 | 처리 |
| --- | --- | --- | --- |
| DEVICE_OFFLINE | 장비가 연결되어 있지 않다 | 연결 상태 offline | 연결 후 재시도 |
```

### MQTT

```markdown
# 포장 라인 — MQTT 규격

- 버전: 4
- 최종 수정: 2026-11-03T06:20:00Z / 홍길동
- 브로커: mqtt://lab.example:1883

## lab/{lineId}/status

- QoS: 1
- Retain: false
- 방향: 장비 → 서버
- Publisher: device
- Subscriber: server
- 용도: 라인 상태 보고
- 대응 Topic: lab/{lineId}/status/ack

### Payload

| 이름 | 타입 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| lineId | string | 예 | 라인 | L1 |
| running | boolean | 예 | 가동 | true |

```json
{ "lineId": "L1", "running": true }
```

### 에러 코드

| 코드 | 설명 | 발생 조건 | 처리 |
| --- | --- | --- | --- |
| LINE_UNKNOWN | 알 수 없는 라인 | lineId 미등록 | 등록 후 재발행 |
```

### WebSocket

```markdown
# 포장 라인 — WebSocket 규격

- 버전: 3
- 연결 URL: wss://lab.example/ws
- 인증: Bearer
- 하트비트: 30초마다 ping

### 종료 코드

| 코드 | 설명 |
| --- | --- |
| 4001 | 인증 만료 |

## command.execute

- 방향: 클라이언트 → 서버
- 종류: Request
- 대응 메시지: command.result

### Payload

| 이름 | 타입 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| name | string | 예 | 명령 | start |

```json
{ "name": "start" }
```

### 에러 코드

| 코드 | 설명 | 발생 조건 | 처리 |
| --- | --- | --- | --- |
| CMD_UNKNOWN | 지원하지 않는 명령 | name 미정의 | 명령 목록 확인 |
```

### 장비 프로토콜

```markdown
# 포장 라인 — 장비 프로토콜

- 버전: 2
- 전송: TCP
- 기본 엔디언: BIG
- 프레이밍: 2바이트 길이 + 본문

## 시작 명령

- Command ID: 0x10
- 방향: 요청
- 대응 명령: 시작 응답

### 필드

| 이름 | 타입 | 필수 | Offset | Length | Endian | Encoding | 설명 | 예시 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| commandId | integer | 예 | 0 | 1 | BIG | UINT8 | 명령 | 0x10 |
| speed | integer | 예 | 1 | 2 | BIG | UINT16 | 속도 | 10 |
| flags.running | integer | 예 | 3 | 1 | BIG | BITFIELD bit 0 len 1 | 가동 | 1 |

### HEX

```text
10 00 0A 01
```

### 해석 JSON

```json
{ "commandId": "0x10", "speed": "10", "flags": { "running": "1" } }
```

### 에러 코드

| 코드 | 설명 | 발생 조건 | 처리 |
| --- | --- | --- | --- |
| SPEED_RANGE | 속도 범위 초과 | speed > 1000 | 값을 낮춰 재전송 |
```

### 일반 문서

```markdown
# 포장 라인 — 설치 가이드

- 문서 버전: 3
- 담당 부서: FW
- 최종 수정: 2026-11-03T06:20:00Z / 홍길동

(저장된 Markdown 본문)
```

## 17. 빈 상태와 오류

- 규격 문서 행이 없음: 생성 버튼 또는 "아직 등록되지 않았습니다."
- 문서는 있고 항목이 없음: 상단 정보와 빈 목록. 이 상태는 초기화가 아니라 생성 직후다.
- 409: 11장. 폼 유지.
- 403: 탭 안에 권한 문구.
- 보관 중 수정 시도: 복구 안내.
- 검증 실패: 해당 칸 옆에 이유를 보여 주고 입력은 유지.
- 네트워크 오류: 저장되지 않았다고 알리고 입력을 유지.

## 18. 1차에 없는 화면

- 공식 규격 문서 삭제, 초기화
- 문서 전체 덮어쓰기
- 항목 하나의 Markdown 복사
- 계정 일괄 등록
- 첨부파일, 결재
- 실시간 편집자 표시
- 필드 단위 자동 병합
- 프로젝트 물리 삭제
